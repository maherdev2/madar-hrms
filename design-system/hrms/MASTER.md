# HRMS — نظام التصميم المعتمد

**المنتج:** أداة عمل داخلية للموظف ومدير القسم وإدارة الموارد البشرية.  
**الواجهة:** عربية باتجاه `rtl` افتراضيًا، مع إظهار الأرقام والرموز التقنية بالاتجاه المناسب.  
**التقنية المستهدفة:** Vue + Inertia + Tailwind.

## الفكرة

تعرض الواجهة مسار الموظف وطلباته بوضوح زمني. أهم عنصر بصري هو **خط سير الطلب**: من الإرسال إلى موافقة المدير ثم اعتماد الموارد البشرية. تبقى الجداول والنماذج هادئة ومنظمة حتى لا يضيع المستخدم بين الإجراءات. هذا اتجاه تشغيلي خاص بالموارد البشرية، وليس تخطيط صفحة تسويقية.

## رموز التصميم

| الوظيفة | القيمة | الاستخدام |
|---|---|---|
| Navy | `#1F3A5F` | عناوين الواجهة والتنقل الرئيسي |
| Teal | `#0F766E` | الإجراء الأساسي والحالة المكتملة |
| Ice | `#E9F3F4` | خلفية عناصر المسار والتحديد الهادئ |
| Canvas | `#F6F8FA` | خلفية التطبيق |
| Ink | `#17212F` | النص الأساسي |
| Line | `#D8E0E7` | فواصل الجداول والحقول |
| Amber | `#A16207` | حالة قيد المعالجة |
| Red | `#B42318` | خطأ أو رفض؛ مع وصف نصي دائم |

- الخط العربي: `IBM Plex Sans Arabic` عند توفيره محليًا؛ البديل `Noto Sans Arabic, Tahoma, sans-serif`. النص اللاتيني والأرقام: `Inter, Arial, sans-serif`.
- أحجام مقترحة: عنوان الصفحة 30px، عنوان القسم 22px، النص 16px، المساعدة 14px. ارتفاع السطر العربي 1.6 أو أكثر.
- مقياس المسافات: 4، 8، 12، 16، 24، 32px. كثافة البيانات متوسطة إلى عالية، مع مساحة لمس كافية للإجراءات.
- الحواف 8px للحقول والأزرار و12px للألواح. استخدم الحدود أولًا، وظلًا خفيفًا فقط عند الحاجة لإظهار طبقة عائمة.
- الأيقونات SVG موحدة؛ لا تستعمل الرموز التعبيرية كأيقونات.

## تخطيط لوحة طلبات الإجازة

```text
سطح المكتب، RTL
┌─────────────────────────────────────────────────────────────────────┐
│ هوية النظام   التنقل                                        الحساب │
├─────────────────────────────────────────────────────────────────────┤
│ عنوان الصفحة + إجراء «طلب إجازة»                                  │
├─────────────────────┬───────────────────────────────────────────────┤
│ رصيد الإجازات       │ طلباتي: بحث/تصفية ثم قائمة قابلة للقراءة    │
│ حالة الطلب الحالي   │ كل صف: النوع، التواريخ، الأيام، الحالة      │
│ خط سير الموافقة     │ فتح التفاصيل يوضح الموافقات والأحداث        │
└─────────────────────┴───────────────────────────────────────────────┘

الهاتف: العنوان والإجراء، ثم الرصيد، ثم الطلبات كبطاقات قائمة مفصّلة.
يظهر خط السير داخل تفاصيل الطلب، ولا تُحشر كل البيانات في صف ضيق.
```

## سلوك الواجهة

- كل إجراء يحمل فعلًا واضحًا: «إرسال طلب إجازة»، «حفظ المسودة»، «إلغاء الطلب». حافظ على اللفظ نفسه في رسالة النجاح.
- تسمية كل حقل ظاهرة دائمًا، ورسالة الخطأ قرب الحقل، وحالة الإرسال معلنة. لا تعتمد على اللون وحده لتمييز الحالة.
- القرار الحساس مثل رفض الإجازة يعرض سببًا مطلوبًا عند الحاجة، ثم يؤكد نتيجة القرار بنص واضح.
- أزرار اللمس لا تقل عن 44×44px. التركيز بلوحة المفاتيح ظاهر. تباين النص العادي 4.5:1 على الأقل.
- اختبر 375، 768، 1024، 1440px؛ لا يوجد تمرير أفقي للصفحة على الهاتف.
- الحركة مرتبطة بفعل المستخدم فقط: فتح التفاصيل، الانتقال إلى خطوة موافقة، أو تأكيد حفظ. احترم `prefers-reduced-motion`.
- حالة القائمة الفارغة تدعو إلى إنشاء الطلب الأول؛ الفشل يوضح ما الذي حدث وما الإجراء التالي.

## ضبط المصدر

استُخدمت مهارة `ui-ux-pro-max` للبحث عن اتجاه لتطبيق عمليات داخلي، ثم راجعت النتيجة يدويًا. واستُخدمت `frontend-design` لصياغة اتجاه خاص بمسار الإجازة ومحتوى الواجهة. تُستخدم `canvas-design` للمرجع البصري الثابت في هذا المجلد؛ ملفات الفن المرجعي ليست أصولًا إلزامية في التطبيق.
